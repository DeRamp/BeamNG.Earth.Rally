2 · A — the button inside the Status cell, no grid change

This is the owner's instruction read literally: the button goes to the right of the pill, in the 260px Status cell, and nothing about the grid changes. The cell has 230px of room (260 less its 30px padding-left). Recce needed is about 129px of that, so about 101px is left — and a row-sized button labelled "Auto recce" is about 100px (15px text at the 900 weight accent secondary forces, plus the button's own .5em of padding each side). It fits by nothing. That is not a measurement, it is arithmetic on the game's stylesheets, and a label that fits by nothing does not fit: a different UI scale, a longer word or another language takes it over the edge.

A1 — a button small enough to be sure: no label

The only way to be sure of the room is to drop the label, which leaves a bare glyph, about 30px wide, in a list where no other cell is separately clickable. The glyph here is a text character standing in for an icon: the game's icon set (ui-vue/src/assets/icons) has no refresh, road or map icon in it, so this form needs an icon drawn before it could ship, and an icon with no label is the one thing on the page that cannot explain itself. The dashed red line is the Status column's right edge at 260px; it is the mock-up's mark, not the game's.

3 · B — a seventh column between Status and Best

The widths. 100px 1fr 130px 260px 160px 150px 30px. Only one track is new and only Name pays for it:

• Status stays 260px. It already holds the longest pill (Recce recommended, about 177px) with its 30px padding and about 50px spare, and the new running pill (about 175px) fits the same room. Taking the 160px out of Status instead would leave 100px, which the amber pill alone overruns.
• the action column is 160px: 24px of padding-left to separate it from the pill, then the widest thing the column ever holds — Auto recce at about 100px, Try again about 92px, Stop about 50px — and about 36px left over for a longer label or another language. It is the one width here with slack in it on purpose: the cell is the only part of the row that changes wording. Everything it holds starts at the same x, which is the whole point of the column.
• Name gives up the 160px: 1fr goes from 1066px to 906px at 1920. The longest name in this rally, "Founders Olmstead, Moore, Nagle Super Special", is about 460px at 20px, so there is no clipping to worry about; the first rally wide enough to care would be clipped today as well.
• the header cell is there and empty. An uppercase AUTO RECCE over a column that is blank on most rows reads as a column of data and advertises, on every row, something half of them cannot do. The chevron column's header is empty for the same reason.

4 · the running state

An auto recce is a sequence of road-graph windows: at a 1000m radius the step is 700m (a window is only trustworthy CORRIDOR_M = 300m inside its own edge), so Starveout, 12.9km, is 19 windows, and each is a real request to BeamNG.Earth that takes seconds. The row has to say how far through it is, and it has to say it in 58px with no second line.

The design: the pill becomes the progress bar. A fourth pill state, working, in the page's blue (--er-blue: #1f8fff), labelled "Auto recce" with the window count in Overpass Mono as every other number on this page is. Its background is a two-stop gradient whose hard edge sits at --er-done, set from the count — so the pill fills left to right as the windows come in. The dot it already has pulses. Nothing else in the row moves, the pill stays about 175px (narrower than Recce recommended), and the state lives exactly where the state already lives.

Why not a separate bar: a bar under the pill needs a second line the row does not have, and a bar across the bottom of the row would collide with the 1px separator and read as a selection. Why no time estimate: plan-1.3.0.md step 3 says the window cost is not measured yet, so the row would be guessing — 19 windows, 7 done is the honest figure and it is also the one that is visibly moving.

5 · how it ends: four rows, four endings, one list

No fifth pill. The pill answers one question — can I drive this stage now? — so an ending puts it back to one of the three answers the page already has, and what happened goes in a line under the card, in the shape of the page's own .er-warnline / .er-msg. Four red rows, four endings, drawn at once:

• SS4 Starveout — done. Green Ready, and the action cell is empty: the button disappearing is the success signal, and the row is now indistinguishable from a stage that never needed one, which is the point.
• SS5 Dalles Mtn Up — not enough map data on disk, partly. 18 of 24 windows had data; the line is matched where there was, and 4.2km has none. That is the amber state, by the letter of store.js — but see the caption below, because the cause is not the usual one.
• SS1 Boyd Loop Very Short — no map data on disk at all. Nothing to match to anywhere on the stage, so the pill stays red and the line is grey, not amber or red: this is a normal outcome for ground the player has never driven, not a failure.
• SS8 Dalles Mtn Down — failed part way. BeamNG.Earth stopped answering at window 12 of 23. The pill is back to red, nothing was written, and the line is the only red thing on the page.

What the drawing turns up, and it is not small. SS5's amber pill says "part of the stage has no road on the map (no notes there) until you drive its recce" — the sentence menu.lua:31 writes. That is true of a gap in the map and false of a gap in the download, and after an auto recce the amber state can mean either. It also undoes the reason notes-1.3.0.md gives for keeping the button off amber rows: that re-running cannot help, because there is nothing there to match to. For a missing-download gap, re-running is the thing that helps, once the player has been over that ground. So either amber has to carry its cause (and keep the button when the cause is the download), or this outcome needs a state of its own. Drawn here as amber + Try again + the sentence, which is the smallest version of the first option.

Disabled is the game's own: opacity: .5 and no pointer events, so the button is still legible and still says what it would do. The reason goes in .er-msg, the amber line the page already uses for a button's answer — next to the row, not inside a tooltip, because a disabled BngButton takes no pointer events and so can never show one. There are two reasons it can be off and they are not the same sentence: api.has('roadGraph') false (an older BeamNG.Earth: the sentence above), or the capability present but the server started without its roads, which the result has to report in words of its own (docs/upstream-roadgraph.md: "it depends on the server having roads at all — has('roadGraph') cannot see that, so the result carries the reason"). In the list, a stage whose auto recce is unavailable has no button in the seventh column at all — eight disabled buttons down a rally with no way to say why is worse than none, and the stage page is where the sentence fits.

7 · what this drawing settles, and what it does not

Settled by drawing it. The button does not fit beside the pill with any confidence (A), so the seventh column (B) is the one to build, at 160px out of Name's 1fr with Status untouched. The running state is the pill itself, filled to the window count, with the sentence in the banner the driven recce already uses. Three endings, no fifth pill: green and no button, amber or red with a line underneath saying what happened.

Not settled, and wanting a decision. (1) Amber now has two causes — no road on the map, and no map data downloaded — and only the second can be fixed by running it again. Carry the cause, or add a state? (2) A stop: is stopping part way worth offering at all, or should a started auto recce just run? It is drawn because a 24-window stage is minutes long, but it is more code and a half-written file to think about. (3) Several stages at once: drawn as disabled-while-busy, which is what the page does today. A rally of nine needs a queue and "Auto recce all" sooner or later, and that button has nowhere to live on this page yet. (4) The hover rule eating the running row's blue border. (5) Whether Auto recce or Match to roads is the better label for a player who has never read the roadmap; "recce" means driving it yourself everywhere else in this UI.

Not verified. Every width here is arithmetic on the game's own stylesheets, not a measurement in a browser: text widths are estimated at roughly .54em per character at weight 600, and a little more at the 900 weight accent secondary forces, so anything said to fit or miss by ten or twenty pixels — A2 above all — is inside the error and has to be checked on screen before it is believed. 1rem is taken as 16px, the game's default UI scale, not a fixed fact; at another scale the row is still 58px (it is in px) while the buttons are not. The row button's size is written here rather than taken from BngButton's small, for the reason in the stylesheet, and whether --bng-button-min-width can be cleared from outside the component is a reading of the variable's purpose, not something seen working. The pills' fourth state, the gradient fill and the blue left border have never been rendered by the game's own stylesheet, only by this file's copy of it.
